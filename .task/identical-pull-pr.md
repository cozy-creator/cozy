Two concurrent pulls of the same checkpoint can both finish transferring bytes, then the second fails `REPOSITORY_CONFLICT` while recording the local repository. Checkpoint and release-lane publication previously used separate CAS transactions.

Record both as one cached-repository transaction. Under SQLite writer coordination, a stale request succeeds only when the current repository already contains its exact checkpoint and active release lane; it preserves current metadata and ownership. Incompatible targets, yanked/malformed repositories and corrupt manifest bytes still refuse. General repository CAS stays strict, and pulls now propagate repository read errors instead of treating them as absence.

All 16 focused native tests passed: 6 new concurrency/integrity cases (including two real barrier-synchronized writers, stale moved lanes and local aliases), 1 strict public CAS case, 8 cache-root ownership cases, and 1 paused-derive retention case. Remote-formatted source hashes match the checked-in bytes. No local builds/tests/CI, new wheel, deployment or live Store/NFS changes.
